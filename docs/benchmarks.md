# Замеры

## M1, первый замер тайлов (2026-10-18)

Проверка главного риска (ADR-0002, ADR-0005): **200 rps на 2 ядрах**.

**Стенд.** Docker Desktop (WSL2) на рабочей машине, профиль «маленький сервер» через
`bench/compose.bench.yml`: у каждого сервиса 2 vCPU и 4 ГБ. api — 2 процесса gunicorn
(`API_WORKERS=2`). Генератор — `grafana/k6` в той же docker-сети, без ограничений.
Данные — слой «Средний доход» из образца (108 977 ячеек, сетка 589 × 635), EPSG:3857.

**Сценарии** (`bench/tiles.js`, 20–30 с, постоянная частота запросов):

- `warm` — 48 тайлов z11–z12 по кругу: после первого прохода всё из дискового кэша;
- `cold` — случайные тайлы z14–z16 по Москве: почти каждый запрос — рендер
  (тайл индексов → значения → классы → PNG).

| Сценарий | Задано, rps | Получено, rps | p50 | p95 | p99 | Ошибки |
|---|---|---|---|---|---|---|
| warm | 200 | 200 | 1,5 мс | 2,4 мс | 5,1 мс | 0 |
| cold | 200 | 200 | 1,9–4,2 мс | 5,5–8,2 мс | 14–83 мс | 0 |
| cold | 300 | 300 | 2,3–2,8 мс | 12 мс | 66–97 мс | 0 |
| cold | 500 | 304 | 1,06 с | 2,04 с | 2,25 с | 0 (5 677 отброшено k6) |
| warm | 1000 | 723 | 513 мс | 695 мс | 821 мс | 0 (8 114 отброшено k6) |

**Выводы.**

- Требование 200 rps на 2 ядрах выполняется с запасом и для холодных тайлов:
  потолок ~300 rps холодных и ~700 rps кэшированных. Холодный тайл — единицы
  миллисекунд (цель ≤ 300 мс). Запасной план ADR-0002 (оптимизация numpy, сервис на Go)
  пока не нужен.
- Первые секунды после перезапуска api медленнее (p95 до ~450 мс при 200 rps): каждый
  процесс загружает раскладку сетки, массив значений и инициализирует pyproj. Лечится
  прогревом (`/v1/cache/warm`, M2) или загрузкой при старте.
- Скорость упирается в CPU процессов api, а не в БД: при попадании в дисковый кэш в БД
  не ходим, при промахе — один запрос метаданных версии.
- **Память.** Кэш тайлов индексов был 4096 записей (до 1 ГБ на процесс) — уменьшен до 512
  (~128 МБ). При перегрузке (1000 rps при потолке ~700) RSS процесса api растёт до
  0,7–0,9 ГБ: очередь запросов и фрагментация malloc. `MALLOC_ARENA_MAX=2` снижает рост
  на 25–30 % без потерь в скорости — включён в образ. См. `known-issues.md`, KI-10.
- Не мерили: мелкие зумы для страны (нужны обзоры, M2), сетки на 10 млн ячеек, `@2x`,
  EPSG:3395 под нагрузкой, сеть между генератором и сервисом.

**Как повторить.**

```sh
docker compose -f docker-compose.yml -f bench/compose.bench.yml up -d --build --wait
python scripts/e2e.py --sample data/layers_sample_2023Q1.zip   # данные
LAYER=$(docker compose exec -T postgres psql -U apc -d apc -tAc   "select id from layer where slug='mean_income_home'")
docker run --rm -i --network pd_geo_sloi_default -e BASE=http://api:8000 -e LAYER=$LAYER   -e MODE=cold -e RATE=200 grafana/k6 run - < bench/tiles.js
```

Имя сети — `<папка проекта>_default` (`docker network ls`).
