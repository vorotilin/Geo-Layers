# Принятые решения (мини-ADR)

Формат: контекст → решение → последствия. Сквозная нумерация, решения не удаляются —
отменённое помечается «заменено ADR-NNNN».

## ADR-0001. Формат ведения решений

- **Контекст:** задание требует фиксировать решения в виде мини-ADR.
- **Решение:** этот файл, одна запись на решение, сквозная нумерация.
- **Последствия:** решения видны команде и заказчику, на них легко сослаться из PR.

## ADR-0002. Python 3.12 + FastAPI

- **Контекст:** основная работа — разбор гео-форматов, проекции, растеризация, KDE,
  PNG. Нужны OpenAPI и быстрый старт. Рассматривали Go (быстрее HTTP, но беднее
  гео-экосистема: GDAL, H3, pyproj пришлось бы вызывать через cgo) и Node.js
  (слабее для численных расчётов).
- **Решение:** Python 3.12, FastAPI, uvicorn под gunicorn. Тяжёлые операции — только
  векторные (numpy, GDAL, scipy), без циклов по пикселям и ячейкам в Python.
  Зависимости фиксируются через `uv` (`uv.lock`).
- **Последствия:** GIL не мешает, потому что горячие участки работают в C. Риск
  по rps проверяем замером на M1. Запасной план, по шагам: (1) оптимизация
  numpy-конвейера и кэша, прогрев тайлов заранее; (2) если не хватит — вынести
  рендер тайла в отдельный сервис на Go (рендер = индексация массива + палитра
  + PNG, гео-библиотеки ему не нужны). Внешний API при этом не меняется.

## ADR-0003. Очередь заданий на PostgreSQL

- **Контекст:** заданиям нужны прогресс, повтор, идемпотентность, капы на токен,
  переживание рестарта — то есть состояние всё равно лежит в БД. Celery добавляет
  брокер и второе место, где живёт состояние. Готовая очередь на PostgreSQL
  (procrastinate) убирает брокер, но держит задания в своих таблицах — прогресс
  и статус для API всё равно пришлось бы вести отдельно.
- **Решение:** таблица `job`, захват через `SELECT … FOR UPDATE SKIP LOCKED`,
  `heartbeat_at` для подбора зависших, `LISTEN/NOTIFY` для мгновенного старта.
  Воркер — тот же образ с командой `worker`.
- **Последствия:** на один компонент меньше. Пропускной способности (десятки
  заданий в минуту) хватает с запасом; при росте можно заменить, не трогая API.
  Цикл воркера пишем сами, поэтому он покрывается тестами в первую очередь:
  двойной захват, падение воркера посреди задания, подбор зависших по
  `heartbeat_at`, повтор с задержкой, отмена.

## ADR-0004. Значения версии — массив float32, а не строки в БД

- **Контекст:** миллионы ячеек × десятки метрик × периоды. Модель «строка на
  значение» даёт миллиарды строк и медленные тайлы.
- **Решение:** у сетки — устойчивая нумерация ячеек `idx`. Значения версии —
  `float32[N]` (`NaN` = нет данных) в S3 с копией на локальном диске; api читает
  через `mmap`. Геометрия ячеек — в PostGIS, один раз на сетку.
- **Последствия:** выборка значений для тайла и пакета точек — индексация массива.
  SQL-агрегаты по значениям напрямую недоступны: агрегат по полигону = PostGIS
  находит `idx` и доли площадей, а numpy считает по массиву. Ячейки сетки только
  добавляются, иначе нумерация сломается. Это осознанное узкое место:
  «удалённая» ячейка в новой версии = `NaN`, а мусор убирает уплотнение сетки
  (см. `known-issues.md`, KI-1).

## ADR-0005. Рендер через «тайл индексов» + пирамиду обзоров

- **Контекст:** 200 rps на 2 ядрах, холодный тайл ≤ 300 мс, стиль меняется без
  перезагрузки данных, любые типы сеток.
- **Решение:** тайл индексов сетки (номер ячейки на пиксель; зависит только от сетки
  и тайловой схемы) кэшируется. Тайл = `palette[classify(values[index_tile])]`.
  Для зумов, где ячейка меньше ~2 px, при публикации строится пирамида обзоров:
  среднее для `intensive`, плотность на км² для `extensive`.
- **Последствия:** смена стиля и новый период не требуют перерисовки геометрии.
  Публикация становится заданием (строит обзоры). Для `rectilinear`, H3 и quadkey
  тайл индексов считается арифметически, для `polygons` — растеризацией.

## ADR-0006. EPSG:3395 как вторая функция проекции

- **Контекст:** Яндекс.Карты v3 по умолчанию используют эллиптический Меркатор;
  тайлы 3857 там съезжают по широте (около 35 км на широте Москвы).
- **Решение:** тайловая схема = функция «пиксель тайла → координаты». Формулы
  сами не пишем: границы тайла в метрах проекции берём из **morecantile** (MIT;
  схемы `WebMercatorQuad` = 3857 и `WorldMercatorWGS84Quad` = 3395), центры
  пикселей внутри тайла — равномерная сетка в этих метрах, перевод в CRS сетки —
  `pyproj`. Остальной конвейер общий. Схема входит в URL тайла.
- **Последствия:** любая новая схема — это ещё одна схема morecantile, без нового
  кода. Главный источник ошибок (ручные формулы проекций) убран. Эталонные
  тесты — по известным координатам и по тайлам Яндекса.

## ADR-0007. Инфраструктура: PostGIS, Redis, MinIO

- **Контекст:** профиль 2 vCPU / 4 ГБ; лицензии должны допускать закрытое
  коммерческое использование.
- **Решение:**
  - PostgreSQL 16 + PostGIS 3.4 — отдельный сервер (GPL у PostGIS не затрагивает
    наш код).
  - Redis 8 — для rate limit и горячего кэша. Лицензия RSAL/SSPL/AGPL на выбор;
    используем AGPL: Redis запускается отдельным неизменённым сервисом, наш код
    ходит к нему по сети и под AGPL не попадает (как MinIO). Если AGPL у
    заказчика запрещён (questions.md, №3) — меняем образ на Valkey 8 (BSD):
    протокол и клиент (`redis-py`, MIT) те же, код не меняется.
  - MinIO (AGPL) — только в локальном `docker compose` как неизменённый отдельный
    сервис; в проде — любой S3.
  - ~~Веб-интерфейс — Jinja2 + HTMX + MapLibre GL JS (BSD) в том же приложении,
    без сборки фронтенда.~~ Заменено ADR-0010.
  - psycopg 3 (LGPL) — используется как библиотека без изменений.
- **Последствия:** один образ приложения, четыре контейнера в compose. Бюджет
  памяти — в design.md §10. Лицензии зависимостей проверяются в CI.

## ADR-0008. Подпись ссылок на тайлы по префиксу пути

- **Контекст:** карта сама подставляет `{z}/{x}/{y}`, поэтому подписать каждый тайл
  заранее нельзя. Если `exp` меняется в каждой ссылке, ломается кэш браузера и CDN.
- **Решение:** `sig = HMAC_SHA256(secret, "{prefix}|{exp}")`, где prefix —
  путь до `{z}`. `exp` округляется вверх до шага `SIGN_EXP_ROUNDING_SECONDS`
  (по умолчанию 1 час, настраивается до суток). Принимаем подпись любым
  из двух активных секретов (ротация).
- **Последствия:** одна подписанная ссылка-шаблон даёт доступ к слою, версии и стилю
  целиком до `exp`. Это осознанно: уровень доступа — «слой», а не «тайл».
  Требует согласования с заказчиком (questions.md, №2).

## ADR-0009. Идемпотентность

- **Контекст:** общие требования разрешают Idempotency-Key или дедупликацию
  по содержимому.
- **Решение:** оба механизма. `Idempotency-Key` на любой `POST` (24 ч, ключ +
  токен → сохранённый ответ; тот же ключ с другим телом → 409). Импорт
  дополнительно дедуплицируется по `sha256(файл) + hash(нормализованный манифест)`
  в рамках namespace.
- **Последствия:** повтор загрузки того же файла не создаёт ни задания, ни версии;
  callback и опрос возвращают один и тот же результат.

## ADR-0010. Веб-интерфейс на Vue 3 (JavaScript) + MapLibre

- **Контекст:** веб-интерфейс обязателен (brief, п. 10). Основная сложность —
  интерактивная карта (слои, прозрачность, легенда, значение под курсором,
  рейтинг, переключение версии, стиля и схемы) и формы манифеста с зависимыми
  полями и сопоставлением колонок. Рассматривали Jinja2 + HTMX (без сборки, но
  карту всё равно писать на чистом JS, а HTMX команде незнаком), Vue без сборки
  (теряются однофайловые компоненты) и Streamlit/NiceGUI (отдельный процесс,
  слабая интеграция с MapLibre и подписанными тайлами).
- **Решение:** Vue 3 на JavaScript (без TypeScript), сборка Vite, MapLibre GL JS
  (BSD). Код — в `ui/`. Без UI-китов: простой CSS. Интерфейс ходит только в
  публичный API `/v1` (обычный `fetch`), своих серверных ручек у него нет.
  Сборка — стадия Node в многоступенчатом Dockerfile; готовая статика копируется
  в образ приложения и раздаётся FastAPI по `/ui`. Вход — по токену API; токен
  хранится в `sessionStorage` вкладки, для карты интерфейс получает подписанные
  ссылки через `POST /v1/tiles/sign`.
- **Последствия:** в итоговом образе нет Node, `docker compose up` по-прежнему
  поднимает всё одной командой, отдельного контейнера для UI нет. UI заодно
  постоянно проверяет публичный API. В проекте два языка: в CI добавляются eslint,
  `vite build` и проверка лицензий npm-зависимостей. Токен в `sessionStorage`
  уязвим к XSS — поэтому строгий `Content-Security-Policy` на `/ui` и никакого
  `v-html` с данными пользователя.
