# Design doc — apc-layers (M0)

Сжато до решений. Обоснования — в `docs/decisions.md` (ADR-NNNN), вопросы — в
`docs/questions.md`. Требования не пересказываем: они в `brief.md`.

## 1. Границы

**Делает:** принимает сетки поставщиков, наборы точек и полигоны; хранит с версиями;
строит слои из точек (KDE, биннинг, картограмма); считает статистику и классы; рисует
растровые тайлы в EPSG:3857 и EPSG:3395; отвечает на запросы к данным (значение в точке,
пакет, агрегат, рейтинг); даёт веб-интерфейс.

**Не делает:** не ходит в БД платформы (щиты присылают координатами пакетом); не хранит
ПД сверх присланного; не геокодирует в обязательном объёме; не ходит в платные сервисы.

## 2. Главная идея

Любой источник — квадраты, гексы, H3, quadkey, районы, результат KDE — приводится к одной
абстракции: **сетка** (`grid`, ячейки `idx = 0..N-1`) + **массив значений** версии
(`float32[N]`, `NaN` = «неизвестно»). Тайлы, значения, агрегаты, рейтинг, статистика,
стили пишутся один раз поверх этой пары — одинаково для слоёв поставщиков и слоёв из точек.

## 3. Архитектура и поток

```
платформа/браузер ──► api (FastAPI, ×2) ──► кэш PNG на диске + mmap-массивы
                              │
                    jobs (PostgreSQL, SKIP LOCKED)
                              │
                        worker (тот же образ)
                              │
              parser-подпроцесс (rlimit, без сети)  ◄── S3 (MinIO) исходники
        геометрия ячеек ──► PostGIS+PostGIS · Redis (rate limit)
```

- **Импорт:** файл → S3 + sha256 → `inspect` (формат/колонки/CRS/20 строк) → клиент
  подтверждает манифест → `import`: парсер потоково пишет чанки Parquet, воркер
  сопоставляет ячейки с сеткой и собирает `float32[N]` + статистику → версия `draft` +
  отчёт → `publish` строит пирамиду обзоров.
- **Тайл:** подпись → кэш на диске → рендер из «тайла индексов» + массива значений +
  стиля → PNG → кэш.

## 4. Данные

| Сущность | Суть |
|---|---|
| `namespace` / `token` | граница приватности; токены хэшем, scopes, отзыв без рестарта |
| `file` / `import` | исходник + манифест; дедуп по `sha256 + manifest_hash` |
| `provider` / `dataset` | набор = группа слоёв одного поставщика |
| `grid` / `grid_cell` | `kind: rectilinear · h3 · quadkey · polygons`; геометрия один раз, `unique(grid_id,key)`, GiST |
| `layer` | `value_kind: intensive` (среднее, доля) `· extensive` (счётчик) — агрегация задаётся у слоя |
| `layer_version` | `period, revision, status(draft/published/archived), values_key, stats` |
| `point_set` / `point_set_version` / `point` | точки с версиями; секционировано по набору |
| `derivation` | происхождение слоя из точек; `auto_rebuild` при пополнении |
| `style` | ревизия входит в URL тайла → смена стиля без сброса кэша |
| `job` / `callback_delivery` | очередь на той же таблице; outbox для callback'ов |

Правила: значения **не** раскладываем в строки — `float32[N]` в S3, api читает через
`mmap` (ADR-0004). Одна сетка на всех поставщиков — ячейки сопоставляются по ключу, новые
дописываются в конец. Полигоны (районы) — тоже сетка. Отсутствие ячейки = `NaN`, не ноль.

## 5. Ключевые решения (решение → почему → чем проверено)

| # | Решение | Почему (факт предметной области) | Проверка |
|---|---|---|---|
| 1 | Тайловая схема = функция; рендерим 3857 **и** 3395 | Web Mercator — на сфере, Яндекс v3 — на эллипсоиде; тайлы 3857 съезжают ~35 км на широте Москвы | известная точка → пиксель в обеих схемах; эталонные тайлы Яндекса (ADR-0006) |
| 2 | Схемы берём из `morecantile` (`WebMercatorQuad`, `WorldMercatorWGS84Quad`), формулы не пишем | ручные формулы проекций — главный источник ошибок | тесты по эталонным координатам |
| 3 | Рендер = «тайл индексов сетки» + `palette[classify(values[idx])]` | тайл индексов зависит только от сетки/схемы, не от версии/стиля → кэш один на всё | цвет случайных пикселей сверяем с shapely-ответом |
| 4 | Пирамида обзоров на зумах «ячейка < ~2 px»: среднее для `intensive`, плотность на км² для `extensive` | m/px зависит от широты; сумма на пиксель зависит от зума — легенда бы «прыгала» | доход (среднее) vs рабочие места (плотность) на z≈5 |
| 5 | KDE с радиусом в метрах — в локальной равновеликой проекции (LAEA), ядро нормировано | радиус в пикселях искажается по широте (`cos φ`); «в метрах» корректно только в равновеликой СК | интеграл ядра = числу точек (1 млн точек) |
| 6 | Статистика потоковая, классы `equal/quantile/log/jenks`, легенда = та же функция breaks | рабочие места — тяжёлый хвост (медиана 2): equal-interval бесполезен | гистограммы двух метрик образца |
| 7 | Потоковый разбор в подпроцессе с `RLIMIT_AS/CPU`, чанки Parquet | 3 ГБ / 10 млн ячеек не лезут в память; файл враждебный | память не растёт с размером файла |
| 8 | Очередь заданий на PostgreSQL (`SKIP LOCKED`) | заданиям всё равно нужны состояние/повтор/идемпотентность в БД | двойной захват, падение воркера, подбор зависших (ADR-0003) |
| 9 | Подпись ссылок по префиксу пути, `exp` округляется до часа | карта сама подставляет `{z}/{x}/{y}`; менять `exp` на каждый тайл нельзя | URL стабилен в пределах часа, ротация 2 секретов (ADR-0008) |
| 10 | Идемпотентность: `Idempotency-Key` + дедуп `sha256(file)+hash(manifest)` | повтор загрузки того же файла не должен плодить версии | тот же файл+манифест → тот же `job_id` |

## 6. API (черновик; полный контракт — `openapi.yaml` с M1)

Правила общих требований §2: ошибки `{error,message,details}`, jobs, курсоры, `X-Request-Id`.

| Маршрут | Назначение |
|---|---|
| `POST /v1/files`, `POST /v1/imports`, `GET /v1/imports/{id}` | файл → `inspect`; манифест → `import`; отчёт об ошибках |
| `GET /v1/datasets`, `/layers`, `/layers/{id}/versions/{v}` | каталог + легенда + шаблон URL + статистика |
| `POST /v1/layers/{id}/versions/{v}/publish` · `/archive` | публикация (строит обзоры) / архив |
| `GET /v1/point-sets`, `DELETE /v1/point-sets/{id}`, `POST /v1/layers/build` | наборы точек; слой из точек `kde/pixel_heatmap/bin/choropleth` |
| `POST /v1/styles`, `PUT /v1/styles/{id}` | стиль; `PUT` = новая ревизия |
| `GET /v1/values`, `POST /v1/values/batch`, `POST /v1/aggregate`, `GET /v1/layers/{id}/rating` | значение в точке / пакет / агрегат / рейтинг |
| `POST /v1/tiles/sign`, `GET /v1/tiles/{layer}/{version}/{style@rev}/{tms}/{z}/{x}/{y}[@2x].png` | подпись; тайл, `tms = 3857 \| 3395` |
| `GET/POST /v1/jobs…`, `POST /v1/cache/warm|purge`, `…/tokens` | задания, кэш, токены |
| `GET /health`, `/ready`, `/metrics`, `/ui`, `/docs` (dev) | служебное |

Большие файлы — по ссылке или ключу S3, не через multipart (SSRF-защита, лимиты).

## 7. Стек (обоснования — ADR-0002…0010)

| Что | Выбор |
|---|---|
| Язык/HTTP | Python 3.12, FastAPI, uvicorn+gunicorn (2 процесса) |
| Гео/расчёты | numpy, scipy, pyproj, morecantile, shapely 2, pyogrio+GDAL, rasterio, h3, pyarrow, Pillow, jenkspy |
| БД | PostgreSQL 16 + PostGIS 3.4 |
| Очередь | таблица `job`, `SKIP LOCKED` |
| Лимиты | Redis 8 (или Valkey, BSD) — только rate limit |
| Объекты | S3; локально MinIO |
| UI | Vue 3 (JS) + Vite + MapLibre GL JS → статика в тот же образ, раздаётся по `/ui` |
| Качество | Alembic, ruff, mypy, pytest, uv; замеры k6 + pytest-benchmark |

Бюджет 2 vCPU / 4 ГБ: Postgres 1 ГБ · Redis 64 МБ · MinIO 256 МБ · api 2×350 МБ ·
worker+расчёт ≤ 1,2 ГБ. Одно тяжёлое задание одновременно.

## 8. Риски

| Риск | Что делаем |
|---|---|
| 200 rps / холодный тайл ≤ 300 мс на Python | тайл индексов + numpy; замер на M1, запасной план — рендер на Go без смены API (ADR-0002) |
| Не распознали сетку как регулярную (10 млн полигонов) | путь `polygons` корректнее, но медленнее; замер на синтетике |
| Файл 3 ГБ / враждебный | потоковый разбор + rlimit + отчёт вместо падения |
| 3395 не совпал с Яндексом | эталонные тайлы, сверка наложением в UI |
| Данные «не как в образце» | синтетические сетки в тестах: H3, гексы, 100 м–5 км, UTM, районы, WKT, 10 метрик |
| Утечка лицензионных данных | только токен/подпись, без значений в логах |

## 9. План этапов

- **M1 (вертикальный срез).** GeoJSON-сетка (образец + синтетика: другой шаг, UTM) →
  `rectilinear` → версия → публикация → тайлы **3857 и 3395** с подписью и кэшем →
  значение в точке; минимальная `/ui` с MapLibre; `docker compose up`; **первый замер
  тайлов** (главный риск).
- **M2 (полный объём).** Остальные форматы и сетки, точки + три метода, полигоны,
  стили/классы, легенда, пакет/агрегаты/рейтинг, обзоры, токены/namespace, callback'и,
  лимиты, весь UI, полный OpenAPI + контрактные тесты.
- **M3 (закалка).** Замеры и оптимизация, README/runbook, known-issues, демо.
  «Желательно»: MVT → PMTiles → картинка области → Shapefile/GeoParquet.

Можно подумать (в дизайне): производные слои (разница периодов = поэлементная операция
над `float32[N]`), слои по времени (точки с `ts` → бин по периоду → версии).
