# Design doc — apc-layers

Этап M0. Согласуется с заказчиком до начала кода.
Объём: 2–4 страницы.

## 1. Границы сервиса

### Что сервис делает

- Принимает файлы сеток данных поставщиков (GeoJSON, NDJSON, CSV, XLSX, GeoPackage)
  через загрузку, ссылку или объект в S3. Описание слоя: название, единица измерения,
  период, поставщик, правило агрегации. Несколько числовых колонок = несколько слоёв.
- Принимает наборы точек (CSV, XLSX, GeoJSON, NDJSON): координаты обязательны,
  вес и категория — по желанию. Хранит с версиями и пополнением.
- Строит из точек слои тремя способами: тепловая карта (KDE с полосой в метрах
  и режимом радиуса в пикселях), биннинг в сетку/H3, картограмма по полигонам.
  Нормировки: как есть, на км², доля от общего, на значение другого слоя.
- Хранит данные в своей модели: набор → слой → версия (период) → значения по ячейкам.
  Геометрия ячеек хранится один раз.
- Считает статистику версии (min/max, квантили, гистограмма) и разбивает на классы:
  равные интервалы, квантили, логарифм, ручные границы. Желательно — Jenks.
- Настраивает стиль без перезагрузки данных: палитра, число классов, непрозрачность,
  цвет «нет данных», правила для мелких масштабов. Легенда строится из того же стиля,
  что и картинки.
- Отдаёт растровые тайлы PNG с прозрачностью в схеме XYZ, 256 px и @2x,
  в двух сетках: EPSG:3857 (Web Mercator) и EPSG:3395 (эллиптический Меркатор,
  как в Яндекс.Картах v3). На мелких масштабах рисует агрегат. Правильные заголовки
  кэширования: Cache-Control, ETag, 304.
- Отдаёт API данных: каталог слоёв и версий с легендой; значение в точке по всем слоям;
  пакет точек (тысячи координат → значения); агрегат по полигону или bbox
  (среднее, сумма, min/max, число ячеек, доля покрытия); рейтинг ячеек или полигонов.
- Версионирует: загрузка создаёт черновик, публикация делает его актуальным, старые
  версии доступны явно, повторная загрузка того же файла не создаёт дубликат;
  пополнение набора точек даёт новую версию слоя.
- Доступ: управляющие вызовы по токену; тайлы и значения по подписанным ссылкам
  со сроком действия (HMAC от пути и срока); CORS; лимиты частоты; наборы точек
  и их слои приватны в рамках namespace.
- Веб-интерфейс: импорт сетки и точек, построение слоя из точек, загрузка полигонов,
  каталог слоёв и версий с публикацией, форма стиля с предпросмотром, карта на MapLibre,
  список заданий с повтором.
- Служебное: прогрев кэша тайлов по области и зумам, сброс кэша, повтор задания,
  метрики, логи, /health, /ready.

### Что сервис НЕ делает

- Не ходит в базу платформы.
- Не знает сущностей платформы (рекламные конструкции, заказы, календарь занятости).
- Не принимает бизнес-решений — только считает, проверяет, преобразует и честно
  отвечает, что получилось.
- Не раздаёт лицензионные данные поставщика без подписи.

### Ограничения

- Стек свободный, защищается в design doc; заказчик вправе отклонить выбор, если он
  мешает эксплуатации (экзотика без пакетов, нет Docker-образов, лицензии).
- Работает в Docker на Linux x86_64, профиль «2 vCPU / 4 ГБ / без GPU» обязателен.
  GPU, если используется, — ускорение, а не требование.
- Никаких платных внешних сервисов: всё считается локально.
- Данные поставщика лицензионные.

## 2. Черновик API

Все маршруты под `/v1/`. JSON, UTF-8. Ошибки — единая форма
`{ "error": "machine_slug", "message": "...", "details": {...} }`.

Черновые ручки (уточняются):
- `POST /v1/datasets` — загрузка сетки
- `POST /v1/points` — загрузка набора точек
- `POST /v1/layers` — построение слоя из точек
- `GET /v1/layers/{id}/tiles/{z}/{x}/{y}.png` — растровый тайл
- `GET /v1/layers/{id}/legend` — легенда
- `GET /v1/values` — значение в точке / пакет точек
- `GET /v1/aggregate` — агрегат по полигону или bbox
- `GET /v1/rating` — рейтинг ячеек/полигонов
- `GET /v1/jobs/{id}` — статус задания
- `GET /health`, `GET /ready`, `GET /metrics`

Полный контракт — `openapi.yaml` (появится на M1).

## 3. Схема данных

По заданию: набор данных → слой → версия (период) → значения по ячейкам.
Геометрия ячеек хранится один раз.

- `dataset` — поставщик, название, единица измерения, период, правило агрегации
- `layer` — ссылка на dataset, тип (сетка / точки / полигон)
- `version` — период, статус (draft / published)
- `cell` — геометрия + `zone_id` (хранится один раз)
- `value` — ссылка на cell + version + число
