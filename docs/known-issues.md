# Известные ограничения и долги

## KI-1. Ячейки сетки нельзя удалить (только добавить)

- **Суть:** значения версии хранятся массивом `float32[N]`, где позиция = номер
  ячейки `idx` (ADR-0004). Если удалить ячейку из середины, номера сдвинутся и
  все ранее сохранённые массивы станут неверными.
- **Когда проявится:** поставщик перезаливает данные и часть ячеек пропала или
  изменила геометрию; сетка со временем копит ячейки, которых нет ни в одной
  актуальной версии.
- **Как живём сейчас:**
  - ячейка, которой нет в новом файле, в новой версии получает `NaN`
    («нет данных») — на карте и в агрегатах она не участвует;
  - если у ячейки с тем же ключом изменилась геометрия — создаётся новая сетка,
    старые версии остаются на старой;
  - лишние ячейки занимают место (4 байта на ячейку в каждой версии и строку
    в `grid_cell`), но на корректность не влияют.
- **Как исправить (план):** служебное задание «уплотнение сетки» — строит новую
  сетку только из живых ячеек, перекладывает массивы нужных версий по таблице
  «старый idx → новый idx», переключает версии на новую сетку, сбрасывает кэш
  тайлов этой сетки. Старая сетка удаляется, когда на неё не ссылается ни одна
  версия.
- **Статус:** не в M1. Делаем в M2/M3, если реальные поставки покажут заметный
  рост «мёртвых» ячеек.

## KI-2. Без Redis rate limit не работает

- **Суть:** счётчики лимитов лежат в Redis (ADR-0007). Если Redis недоступен,
  запросы пропускаются без лимита (fail-open), в лог пишется предупреждение,
  `/ready` показывает деградацию.
- **Почему так:** отказывать всем клиентам из-за падения вспомогательного
  компонента хуже, чем временно не ограничивать частоту.
- **Статус:** осознанное поведение; при необходимости меняется на fail-closed
  настройкой.

## KI-3. Подписанная ссылка — доступ к слою целиком и чуть дольше срока

- **Суть:** подпись покрывает префикс пути (слой + версия + стиль + схема), а не
  отдельный тайл (ADR-0008). Срок округляется вверх до `SIGN_EXP_ROUNDING_SECONDS`
  (по умолчанию 1 час), поэтому ссылка может жить дольше запрошенного на этот шаг.
- **Почему так:** карта сама подставляет `z/x/y`; стабильный URL нужен для кэша
  браузера.
- **Статус:** ждём ответа заказчика (questions.md, №2); шаг округления
  настраивается.

## KI-4. Токен веб-интерфейса уязвим к XSS

- **Суть:** интерфейс хранит токен API в `sessionStorage` вкладки (ADR-0010);
  внедрённый на страницу скрипт мог бы его прочитать.
- **Как живём:** строгий `Content-Security-Policy` на `/ui`, никакого `v-html`
  с данными пользователя, токен живёт только до закрытия вкладки.
- **Как исправить (план):** вход через httpOnly-cookie с короткой сессией на
  стороне сервера.

## KI-5. Одно тяжёлое задание за раз

- **Суть:** на профиле 2 vCPU / 4 ГБ воркер выполняет одно тяжёлое задание
  (импорт, KDE, пирамида) одновременно (design.md §10). Остальные ждут в очереди.
- **Когда проявится:** несколько больших импортов подряд — последний начнётся
  через десятки минут.
- **Как живём:** число параллельных заданий настраивается; капы на токен;
  прогресс и позиция видны в `/v1/jobs` и в интерфейсе.

## KI-6. На мелких масштабах счётчики — плотность, а не сумма

- **Суть:** для `extensive`-слоёв (рабочие места, число точек) на зумах, где
  ячейка меньше ~2 px, рисуется плотность на км², а не сумма (design.md §5.3).
  Легенда при этом меняет единицу.
- **Почему так:** сумма на пиксель зависит от зума и на разных масштабах даёт
  несравнимые цвета. Brief допускает «сумму или плотность».
- **Статус:** осознанное решение; пользователь видит смену единицы в легенде.

## KI-7. Тепловая карта «радиус в пикселях» — без единиц

- **Суть:** визуальный режим считается на лету при рендере, зависит от зума,
  поэтому легенда относительная («меньше — больше»), без физических единиц.
- **Как живём:** в каталоге слой помечен как визуальный; для измеримой плотности —
  KDE с полосой в метрах.

## KI-8. KDE на большие области — по регионам, возможны швы

- **Суть:** KDE считается в локальной равновеликой проекции (LAEA); для охвата
  больше ~1500 км область делится на регионы (design.md §6). На стыках регионов
  возможны небольшие разрывы значений.
- **Как живём:** регионы перекрываются на 3 полосы ядра, значения на стыке берутся
  из ближайшего центра; размер растра ограничен конфигом (иначе 422).
- **Статус:** проверяем на синтетике на всю страну в M2.

## KI-9. Публикация версии не мгновенная

- **Суть:** при публикации строится пирамида обзоров для мелких масштабов
  (ADR-0005), поэтому `publish` — фоновое задание (202), а не мгновенное
  переключение.
- **Когда проявится:** на сетке в 10 млн ячеек публикация займёт минуты.
- **Как живём:** до окончания задания текущей остаётся прежняя версия; прогресс
  виден в `/v1/jobs`.
